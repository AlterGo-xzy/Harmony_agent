# Quality Definition

ArkTS product code is considered acceptable in this kit only when all of the following hold:

- it compiles, or any remaining compiler issue is explicitly documented
- it passes the linter, or remaining issues are explicitly documented
- it does not leak unsupported source-language constructs
- it follows ArkTS-native patterns instead of generic TypeScript habits
- it is grounded in a relevant guide, template, example, or recipe from this repo
- it has been checked against diagnostics and repair guidance when errors occurred

This document is the authored review policy source.
